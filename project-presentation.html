Health check scheduler.

A compact conversational application that turns symptom context into a responsible specialist recommendation—and then into a confirmed appointment.

01.1 · Experience

One conversation, from concern to confirmation.

The user never leaves the transcript. Natural language handles symptom collection; focused inline controls handle every scheduling decision.

STEP 01

Describe

Share the main concern in everyday language.

STEP 02

Enrich

Add optional history files or prior symptom context.

STEP 03

Clarify

Answer two to four relevant follow-up questions.

STEP 04

Route

Receive one evidence-linked specialty recommendation.

STEP 05

Schedule

Choose a location, duration, date, and time.

STEP 06

Confirm

Save a local appointment and confirmation code.

01.2 · Runtime

Complete locally. Enhanced optionally.

The deterministic engine owns every required capability. A language model is a replaceable enhancement—not the foundation of the product.

Private, predictable, self-contained.

Conversation, document extraction, routing, scheduling, and persistence all execute in the browser using validated rules and browser-local data.

  • No symptom content sent to a server
  • Full upload and scheduling functionality

01.3 · Modules

Small modules, strict boundaries.

Each capability can be tested, replaced, and evolved independently without turning the conversation into a single opaque decision.

01

Conversation state

Enforces legal transitions from symptom intake through recommendation, scheduling, and confirmation.

02

Safety policy

Runs deterministic urgent-warning checks before routing and stops routine scheduling when needed.

03

Context extractor

Reads supported local files, identifies symptom facts, and requires user review before using them.

04

Routing knowledge

Combines the bundled catalog with active, validated symptom-to-specialty mapping packs.

05

Scheduling engine

Generates duration-aware slots, excludes local conflicts, and validates the selection at confirmation.

06

Browser persistence

Stores approved extracts, imported mappings, conversations, and demo appointments on the device.

01.5 · Safety

Routing assistance, never diagnosis.

Safety policy is immutable and deterministic. Neither an imported mapping nor a language model can weaken it, skip it, or continue routine scheduling after an urgent exit.

Non-negotiable behavior
Urgent warning signs stop the routine booking flow.
Before every route

Current user statements pass through the deterministic warning-sign policy.

Historical context

Old urgent phrases trigger a question about whether the symptom is happening now.

Low confidence

Unclear or conflicting evidence falls back to primary care instead of false precision.

Allowed output

The system recommends one cataloged specialty with a concise, evidence-linked rationale.

Private by default

Raw uploaded files stay in memory and are never persisted or sent to a model.

Explicit limits

The product identifies itself as a demonstration and not a diagnostic medical system.

01.6 · Scheduling

A structured flow inside the chat.

Conversational guidance and precise controls work together: the transcript explains each step while inline widgets prevent ambiguous scheduling choices.

From recommendation to reserved slot.

Availability is generated from fictional clinic hours for the next 30 days. Earlier changes clear dependent choices, and the slot is revalidated immediately before a local confirmation is created.

01.7 · Delivery

Build the dependable core first.

Delivery proves the no-model application before adding document knowledge or optional conversation enhancement.

PHASE 01

Foundation
